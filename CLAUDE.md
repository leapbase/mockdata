# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`mockdata` is a hybrid synthetic data generator (TypeScript/Node, React UI), modelled on `~/git/syda` but fixing its gaps. Deterministic generators handle structure, keys, numbers and dates; an LLM is meant to fill only semantic free-text columns.

Open source under AGPL-3.0-or-later (`LICENSE`; `license` field in every `package.json`) at https://github.com/leapbase/mockdata, and the hosted copy at https://mockdata.com is free to use, so README and landing copy are public. The landing footer's source link is how the hosted site meets AGPL section 13 (offer network users the source); keep it, and `Landing.test.tsx` checks it.

Implemented so far (hosted MCP with per-user API keys included): `packages/core`, `packages/llm`, `packages/inputs`, `packages/cli`, `packages/mcp`, `packages/server`, `packages/web`, plus accounts (`packages/auth-kit`, `packages/accounts`, wired into `server` and `web`). Run history and a visual schema builder are not built.

`packages/cli/src/cli.ts` exports async `run(argv, io)`, which resolves to an exit code and never calls `process.exit`, so tests call it directly (`io.llm` injects a fake provider). `bin.ts` is a thin wrapper. Commands: `generate <schema> [-o dir] [-f json|ndjson|csv] [-s seed]`, `validate <schema>`, and `infer <source>` (see Input loaders). Without `-o` generate prints JSON to stdout; csv/ndjson need `-o`.

Vitest aliases `@mockdata/core` to its source (`vitest.config.ts`), so tests need no build.

## Core architecture (`packages/core/src`)

- `schema.ts`: Zod schema plus `parseSchema`, which also cross-validates refs (target must exist, be primaryKey/unique, and have the same type) and `after` rules.
- `graph.ts`: `generationLevels` groups tables so parents come first and throws `CycleError` on FK cycles (never guesses an order). Self references are excluded there and handled per row. `columnOrder` sorts columns within a table by `after` dependencies.
- `generate.ts`: `generate(schema, {seed})` walks the levels, fills each row, then runs `validate`, which hard-fails on violations (enum, min/max, unique, null, orphan FK, `after`). Constraints are enforced by construction and re-checked, not left to a prompt.

Schema DSL points that are easy to miss:
- FK is `ref: "table.column"`, with optional `distribution: "zipf"`. A self reference only samples earlier rows, so it should be `nullable`.
- `within: n` (with `after`) bounds a date to at most n days after its source, so gaps like a hospital stay stay realistic; `validate` re-checks it.
- Cross-column rule is `after`: `"col"` for the same row, `"fkCol.parentCol"` to read through a foreign key to the parent row.
- Output is deterministic per `seed` via a seeded Faker instance.

- `pattern` is a regex, generated with `faker.helpers.fromRegExp` and re-checked anchored in `validate`.
- Cardinality lives on the FK column: `unique: true` means one-to-one, `maxPerParent: n` caps children per parent. `pickParent` probes forward from the sampled parent when one is full, so caps hold under zipf skew; it throws if total capacity is too small.
- Cycles: `planGeneration` (in `graph.ts`) defers a *nullable* FK that lies on the cycle. That column is left null on the first pass and filled by `fillDeferred` after all tables exist. With no nullable FK on the cycle it still throws `CycleError`. `after` rules that read through a deferred FK throw `GenerationError`.

## LLM layer (`packages/llm/src`)

Only columns marked `llm` (string type) go to a model; everything else stays deterministic.

**Provider settings come from `.env`** (git-ignored; `.env.example` lists the names). The CLI merges `./.env` under the real environment (real env wins) and passes it to `resolveLlmConfig` (`config.ts`), where the schema's optional top-level `llm: {provider, model, baseUrl, batchSize, maxRetries, apiKeyEnv}` block wins over the environment:
- provider <- `AI_PROVIDER` (anthropic | openai | ollama | openai-compatible); model <- `ANTHROPIC_MODEL` / `OPENAI_MODEL` / `OLLAMA_MODEL` by provider (no default on purpose).
- `ollama` uses the OpenAI chat format at `OLLAMA_BASE_URL` (host only; `/v1` is appended; default localhost:11434), no key. Keys: `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`.
- Errors name variables, never values. Never print or commit `.env`; to inspect it list variable names only.

- Core support: `generate(schema, {deferLlm: true})` leaves llm cells `undefined` (pending; `null` means intentionally null via `nullable`/`nullRate`) and skips validating them. Plain `generate()` throws on llm columns so they are never silently empty.
- `generateWithLlm` (`fill.ts`) = deferred generate, `fillLlmColumns`, then full `validate`. Columns fill one at a time, parent tables before child tables (via `planGeneration` levels, then schema order), in batches (default 20 rows). Replies must be a JSON array of exactly N strings; bad replies, 429s and 5xx are retried with backoff (default 3 retries), 4xx auth errors are not. `unique` columns re-ask for duplicates (max 3 rounds) with an "avoid" list.
- Parent-row context (`context.ts`, `createContextBuilder`): each row's prompt shows its own values plus, up to `llm.contextDepth` hops (default 1, max 2, 0 = off), the rows it references. A foreign key id is replaced by the parent's values under a name derived from the column (`product_id` -> `"product": {...}`; falls back to the column name on a clash), the parent's key and unexpanded ids are dropped, strings clip at 60 chars, parents show at most 6 columns. Parent rows are looked up live, so text the model wrote for a parent appears in its children's prompts. The prompt only carries the "nested value = related row" sentence when the table has foreign keys and depth > 0.
- Truncation: output budget is `256 + 150 * rows` tokens (max 8192). A cut-off reply (provider `truncated` flag from `stop_reason`/`finish_reason`, or an unclosed `[` as fallback) is retried with the limit doubled rather than repeated; at the cap it fails with advice to lower `llm.batchSize`. (Found live: a 100-per-row budget cut off descriptive text and doubled cost through retries.)
- `provider.ts`: raw `fetch` to Anthropic Messages and OpenAI chat completions (ollama / openai-compatible = same wire format + base URL, key optional). Requests time out after 120s (retryable) so an unreachable host cannot hang the CLI.
- Tests use fake `fetch`/providers only (CLI tests use an empty temp cwd so a real `.env` never leaks in). A live run against Ollama has been verified manually; Anthropic/OpenAI request shapes are not yet verified live. LLM output is not reproducible by seed (only the deterministic columns are).
- Known limits: no cost estimate (tokens only), calls are sequential, parent context is repeated per row (no dedup of shared parents), and a child's other parents are not shown to a parent's own prompt (context only flows child <- parent).

## Input loaders (`packages/inputs/src`)

Build a schema from an existing source; every loader returns `{schema, warnings}` and ends in `finalize` (`common.ts`), which re-checks the result with `parseSchema` + `planGeneration` and turns any problem into a warning so the user still gets a file to fix. Warnings are part of the output contract: anything skipped, guessed or approximated must be reported.

- `jsonschema.ts` `fromJsonSchema`: JSON Schema, OpenAPI 3.x/Swagger 2, and Pydantic `model_json_schema()` output. Each object schema is a table; nested objects/arrays are skipped with a warning; optional properties become nullable; `<thing>_id` / `<thing>Id` links to a table named <thing> with a same-typed `id`. Explicit overrides: `x-mockdata-ref`, `x-rows`. Local `$ref` only.
- `sample.ts` `inferFromSamples` / `parseSample`: CSV (own RFC 4180 parser), JSON, NDJSON, or a folder of files. Infers types, ranges, null rates, small enums, faker hints by column name, foreign keys (name-based, subset-checked), zipf skew, one-to-one, and `after` date rules only when they hold in every row and there are at least 20 rows. Copies shape, never rows; enums do copy observed values of low-cardinality columns (`enums: false` / `--no-enums` disables).
- `db/`: `catalog.ts` (`RawTable` -> schema; `mapDbType`) plus one introspector per dialect: `sqlite.ts` (built-in `node:sqlite`, PRAGMAs, opened read-only), `postgres.ts` (`information_schema` + `pg_constraint`, in a `begin read only` transaction, default schema `public`), `mysql.ts` (`information_schema`, read-only session; URL must name the database). Each takes an injectable `query` function so tests need no server. Queries run sequentially (one connection, one query at a time). Only catalog metadata is read, never table rows. `db/index.ts` `inferFromDatabase` redacts passwords from every error.
- Not supported and reported as warnings: composite primary/unique/foreign keys, views, non-scalar types (mapped to string), self-referencing NOT NULL foreign keys (forced nullable).
- `source.ts` `inferFromSource` detects the kind from a URL/extension/directory; sample files over 100 MB are refused.
- Python models: Pydantic goes through `Model.model_json_schema()` -> `fromJsonSchema`. There is no SQLAlchemy helper script; create the tables in a SQLite file (`Base.metadata.create_all`) and infer from that.

Verified against real engines (Postgres 16 server, MySQL 9.3 server, SQLite) in throwaway instances; the automated suite uses SQLite files, `@electric-sql/pglite` (real Postgres, in-process) and canned MySQL rows. A live MySQL test runs when `MOCKDATA_TEST_MYSQL_URL` is set (it expects tables `mockdata_customers`/`mockdata_orders`). Connection strings should go in `.env` and be used as `mockdata infer env:VAR`, so they never appear on a command line.

## MCP server (`packages/mcp/src`)

`createServer({root, env, llm})` in `server.ts` (official `@modelcontextprotocol/sdk`, stdio via `bin.ts`; register with e.g. `claude mcp add mockdata -e MOCKDATA_ROOT=/some/dir -- node <repo>/packages/mcp/dist/bin.js`). Tools: `describe_schema_format` (text in `reference.ts`, keep it in sync with the schema DSL), `validate_schema`, `infer_schema` (path under root, inline content, or `connectionEnv`), `generate_data` (row counts + capped preview; optional `outputDir`/`format`/`overwrite`), `get_run_report` (last run, in memory). Reuses `loadEnv`/`parseSchemaText`/`serialize` from `@mockdata/cli`. `bin.ts --http [--port n] [--allow ranges] [--host addr]` serves Streamable HTTP at `/mcp` via `startMcpHttp` (`http.ts`): 127.0.0.1 only unless `allow` is given, Host/Origin checked with `localRequestProblem` (shared with the web UI server, from `@mockdata/cli`), one server per session so `lastRun` is per client, capped sessions, no auth on purpose (never expose it). Tests: `mcp/test/http.test.ts` uses the SDK client against port 0.

Tool inputs come from an agent, so file access is strict: `schemaPath` and `outputDir` must be relative and stay inside `root` (`resolveInside` also blocks symlink escapes), `schemaPath` must be .yaml/.yml/.json and never `.env*`, existing files are never overwritten without `overwrite: true`, and conflicts are checked before any LLM call. stdout is the protocol channel: never `console.log` in this package or anything it imports; use stderr.

`infer_schema` never accepts a connection string from the caller: `connectionEnv` names an env var/.env entry, the name must be upper-case and mention DATABASE/DB/POSTGRES/MYSQL/MARIADB/SQLITE (so it cannot be pointed at an API key), the value must be a supported database URL, and values are never echoed. `path` follows the same root confinement and `.env` rules as `schemaPath`.

Schema hardening that exists because schemas may be untrusted: table names must match `^[A-Za-z_][A-Za-z0-9_-]*$` (they become file names), and `faker:` must be `module.method` with no `constructor`/`prototype` segments and not `helpers.fake`/`mustache`/`fromRegExp`.

## Web UI (`packages/server`, `packages/web`)

`createApp({root, env, llm})` (`server/src/app.ts`) is a plain Node `http` handler (no framework); `startServer` listens on 127.0.0.1 unless given `allow` (private CIDRs from `parseAllow`; then 0.0.0.0, see Network access below), `bin.ts` is `mockdata-ui [root] [--port] [--allow ranges] [--host addr]` (`npm run ui`). Routes: `GET /api/config|files|file`, `PUT /api/file`, `POST /api/file/rename|validate|generate|generate/stream|infer|export`. Rename (`renameFile` in `routes/files.ts`) writes the new name create-only through `writeFileConfined`, then unlinks the old file (a symlink source is refused), so it never overwrites and a failure keeps the original. In the UI the header name field is the only place to name or rename a schema, and its Save button is enabled when the text or the name changed. Tests boot a real server on port 0 with `boot()` in `server/test/helpers.ts` (fake LLM provider via `llm`, temp root, empty env).

It treats the browser like an untrusted MCP caller: path confinement, the `.env` rule, `connectionEnv` names and `inferConfined` live in `packages/cli/src/confined.ts` and are shared with `packages/mcp` (change them once; errors must never echo a caller-supplied value). Confinement is symlink-safe: `resolveInside` inspects every link on the path (dangling ones included), writes go through `assertNotSymlink`, and reads through `assertNotEnv` (a schema-named link to `.env` is refused). Requests need a localhost `Host`/`Origin` and `Content-Type: application/json`; static files carry a CSP. `/api/generate/stream` is SSE over POST (the schema text is the body); closing the connection aborts the run through `generateWithLlm`'s `signal` (checked between batches; a request already in flight finishes). Preview is capped at 200,000 rows total and reports `pending` LLM columns (cells still `undefined`). `/api/config` returns the LLM provider name or the reason it is unavailable, plus database env var names, never values.

`packages/web` is Vite + React 19 + CodeMirror 6, with React Flow for a read-only schema diagram (`diagramLayout.ts`: Dagre lays it out at once, then ELK's layered algorithm, with a fixed port per column handle, replaces it from a Web Worker; `elk-worker.min.js` ships as a separate ~1.6 MB asset, exempted in `bundle.dist.test.ts`; LR/TB direction is kept in `localStorage`), no router; `App.tsx` holds workspace state. `Root.tsx` picks the page: `/` is the landing page (`src/landing/`, static copy in `content.ts` that must describe only real features; sample rows are real `shop.yaml` output) and `/app` is the workspace; both are lazy chunks (`bundle.dist.test.ts`). The server serves `index.html` for exactly `/app` and `/app/` (`static.ts`), never as a catch-all. Account emails link to `/app#verify_token=`/`#reset_token=` and Google redirects to `/app`; `Root` forwards older `/#…_token=` links. Colours are tokens on `:root` in `styles.css` with a dark set (system preference, or `data-theme` on `<html>` from the header `ThemeToggle`, stored in `localStorage` via `theme.ts`); CodeMirror and React Flow follow `useResolvedTheme`, and diagram edges use `var(--edge)`. `AuthGate` supplies the branded header and account menu. The left sidebar has Schemas and embedded Import tabs; the center has Editor/Diagram views; generation and export live in a collapsible right panel (closed initially). Responsive overlays use `drawers.ts` for Escape, focus trapping, and focus restoration. Fonts are bundled locally through Fontsource. `/api/validate` additionally returns `diagram.tables` with named columns, types, key/nullability flags, and references, excluding model configuration and prompts. Its API types in `api.ts` mirror the server's responses by hand. Tests stub `fetch` (`test/stub.ts`) and mock the CodeMirror `Editor` component (jsdom cannot lay it out), so the real editor is only exercised in a browser.

## Network access

Both servers are localhost-only by default. `packages/cli/src/network.ts` (shared, exported from `@mockdata/cli`) holds the opt-in: `parseAllow` (single IPs, CIDRs, `a.b.c.x` = /24; only 10/8, 172.16/12, 192.168/16, 100.64/10, at most /16 wide, else `NetworkConfigError`), `listenPlan` (bind 127.0.0.1, or 0.0.0.0 with an allow list; a non-loopback host without one throws), `dropForeignConnections` (destroys sockets outside the list), `remoteAllowed` (loopback always), and `hostnameAllowed` (Host/Origin: localhost, or an IP literal in the list or on a local interface; never a name, for DNS rebinding). `localRequestProblem(host, origin, access?)` in `confined.ts` applies it, and the Origin must still be same-origin with the Host. On top of the allow list there is a shared secret: `MOCKDATA_TOKEN` (`tokenFromEnv`: 16+ chars of `[A-Za-z0-9._~-]`, from env or `.env`; no CLI flag so it stays out of `ps`) or a generated one (`listenPlan` returns `tokenGenerated`, bins print it). `needsToken` exempts loopback peers (`trustLoopback`, default true; tests set false to exercise it over loopback), everyone else must pass `tokensEqual` (constant time). Web UI: `presentedToken` reads a Bearer header or the `mockdata_token` cookie, and a GET of a non-API path with `?token=` becomes a `HttpOnly; SameSite=Strict` cookie plus a redirect without the token (`app.ts`). MCP HTTP accepts the Bearer header only. Errors and responses never contain the token. Traffic is plain http, so say so in any new docs. Tests inject `localHosts` instead of reading interfaces.

## Accounts (`packages/auth-kit`, `packages/accounts`, `server/src/accounts`, `server/src/routes/auth.ts`, `web/src/AuthGate.tsx`)

Opt-in third mode, on iff `MOCKDATA_PUBLIC_URL` is set (env or `.env` under the config root): everyone signs in, **loopback is never trusted** (a TLS proxy connects from loopback), no token, no allow list (`listenPlan` refuses `--allow` with it). Needs Node 22.13+ (`node:sqlite`, loaded lazily so local mode still runs on older Node).

- `packages/auth-kit` is a vendored copy of itravelmap's `auth-kit` (source commit in its README; Express middleware and WeChat removed, `nodemailer` pinned): scrypt hashing, validation, single-use verification/reset tokens, `AuthService`, mailer, and the `AuthAdapter` interface. It has **no** sessions, cookies, Google flow or rate limits; those are ours.
- `packages/accounts`: `AccountsDb` (opens `<dataDir>/accounts.db`; every top-level operation goes through `gated` so a statement cannot land inside another request's open transaction; code inside a transaction must not call `gated`), `SqliteAuthAdapter`, `SessionStore` (cookie holds a random id, only its SHA-256 is stored, sliding 30-day expiry and a 90-day absolute cap; cookies are `__Host-`-prefixed over https via `sessionCookieName`/`oauthCookieName`), `OAuthStates` (state is single-use and only valid with the nonce in the browser's own cookie), `RateLimiter`, quotas (`limitsFromEnv`, `UsageStore`, `RunGate`, disk quota), emails. Users have a random `dirId` for their folder, never derived from email or a provider id.
- `server`: `createAccounts`/`accountsFromEnv` build the runtime; `app.ts` resolves the session before routing and builds a per-request ctx whose `root` is `<dataDir>/users/<dirId>` (created on first use, verified a real directory) while `env` still reads the operator's `.env` from the config root. `routes/auth.ts` holds the `/api/auth/*` routes (anti-enumeration: register answers 202 for new and existing addresses, forgot/resend always `{ok:true}`, all padded with `padToTimingFloor`; verify-email never logs in; reset/change revoke sessions). `accounts/google.ts` is a hand-rolled authorization-code flow with PKCE (userinfo endpoint, requires `email_verified`, no CSP change). `accounts/guards.ts` (`beginRun`) enforces the row cap, daily LLM budget and run slot and strips `provider/model/baseUrl/apiKeyEnv` from a schema's `llm` block; `connectionEnv` inference and `dbEnv` names are off in this mode. The account DB lives outside every user root (a user-writable `.json` inside one would be writable through `PUT /api/file`).
- `web`: `AuthGate` wraps `<App/>` in `main.tsx` (`GET /api/auth/me`: accounts off means render the app untouched; a 401 from any non-`/api/auth/` call via `setOnUnauthorized` returns to sign-in; `key={user.id}` remounts the app per user). `ApiError` now carries `status` and `code`.
- Hardening from the security review (keep these): every sign-in attempt is counted **before** hashing (`loginIp`), hashing goes through `acc.hashing` (Semaphore 2 + queue 16, then 503), failed sign-ins are tracked per mailbox+address and per mailbox (high threshold), IPv6 clients are keyed by /64 and `trustProxy` defaults on for https; mail is queued after the response (`acc.queueMail`, never awaited, emails redacted from logs); registering over an already-registered address never changes it (no overwrite: an overwrite lets an attacker re-register before the owner clicks and have the owner's click verify the attacker's password), an unverified one is mailed another link limited per mailbox, and **verifying needs the link AND the sign-up password** (`POST /api/auth/verify-email`, which peeks the token, checks the password through `acc.hashing`, then consumes it and signs in; the real owner of a squatted address recovers with Forgot password); reset consumes its token inside the hashing slot so a 503 cannot burn it; addresses must match a plain-ASCII regex (a mail library would split `a,b@x` or `Name <b@x>`); emailed links use a URL fragment (`#verify_token=`, `#reset_token=`); `referrer-policy: no-referrer` on every accounts-mode response; unexpected 500s return a generic message (detail to stderr only) via `errors.ts`; `lockedLlmConfig` clamps batch/retries/context and `assertSchemaShape` caps tables, columns, name length (64), cells and prompt length; the per-user and server-wide daily budgets are checked and charged in one gated step (`UsageStore.reserveLlmRows`); heavy routes are limited to 30/min per user, schema checks to 120/min, password changes to 5 per 15 min; `setBodyLimit` caps chunked bodies in accounts mode; 502s and model-config errors are replaced by generic text (`errors.ts`). `packages/core` generation is linear: `ParentUsage` (union-find over full parents, same picks as the old linear probe) and `lookupRow` (indexed parent rows for `after: fk.col`); both were quadratic and a small schema could otherwise block the event loop for minutes. Not done on purpose or yet: per-token spend accounting (retries and unique re-ask rounds are not charged), CAPTCHA/domain allowlist, counting empty directories, prioritising known users when the hashing queue is full.
- Invariants: auth errors are generic and never echo input; no token, code or session id in any response or log; new secrets (`SMTP_PASS`, `GOOGLE_CLIENT_SECRET`) must not match `DB_ENV_NAME` or `*_API_KEY`/`*_API_TOKEN`. Tests use a capturing mailer, fake `fetch`, `:memory:` SQLite and `bootAccounts()` in `server/test/helpers.ts`. A real SMTP send and a real Google sign-in are manual-only (need credentials).

### Hosted MCP and API keys (`accounts/src/apikeys.ts`, `server/src/accounts/mcp.ts`)

Accounts mode also serves MCP at `/mcp` (`createHostedMcp`, mounted in `app.ts` before `/api/`). Auth is a per-user API key (`ApiKeyStore`: `md_` + 32 random bytes, SHA-256 stored, max 10 per user, `last_used_at` written at most every 5 min) in `Authorization: Bearer` only, never the cookie. Keys are managed by session-authenticated `GET/POST /api/auth/keys` and `POST /api/auth/keys/revoke`; reset-password calls `revokeAll`. The DB schema is version 2 (`MIGRATIONS` in `db.ts` upgrade older files in place). Tools come from `@mockdata/mcp` `createServer({root, hosted})`: `HostedHooks` supply the operator env (never `.env` under the user's root), `beforeValidate` (throttle + `assertSchemaShape`), `beforeInfer` (throttle; `connectionEnv` refused), `generate` (`beginRun` then the runner's `sample` job, errors replaced through `publicMessage`), `beforeWrite` (disk quota), and `describeError` (`describeHostedError`: every tool error goes through `publicMessage`, so a hosted caller never sees a raw file system error or server path). Without `hosted` the MCP server behaves as before. Sessions use the shared `McpSessions` (`mcp/src/sessions.ts`, also behind `startMcpHttp`): owner-bound (another owner's session id is a 404), per-owner and global caps, idle sweep. Limiters: `mcpUser` 240/min, `apiKeyFail` 30/15 min per address, `apiKeyUser` 20 key creations/hour. The web account menu's `ApiKeys` dialog shows a new key once plus the `claude mcp add` command; the landing page's MCP copy points at `https://mockdata.com/mcp` (`MCP_URL` in `landing/content.ts`). Tests: `server/test/accounts-mcp.test.ts` (SDK client against a real server), `accounts/test/apikeys.test.ts`.

### Worker threads (`server/src/workers/`) and measured capacity

Generation no longer runs on the server's event loop. Preview, run and export are each one **job** (`job.ts`: `runJob` is the single pipeline: generate deferred, fill model columns, validate, then build the preview or serialize/zip) handed to a `Runner` (`runner.ts`). `InlineRunner` runs it on the calling thread (tests, `MOCKDATA_WORKERS=0`, and whenever a test hook `ctx.llm.provider/fetch/sleep` is set, since functions cannot cross threads); `WorkerPool` (`pool.ts`) runs it in `worker_threads` (`worker.ts`, message types in `protocol.ts`, built by `factory.ts` `createRunner`/`poolSettingsFromEnv`). Only a small result crosses back (preview object, or strings / a transferred zip buffer), never the dataset. Pool behaviour: lazy spawn up to `size`, bounded queue (`BusyError` -> 503), per-job time limit that starts when the worker posts `ready` (-> `JobTimeoutError`, 504, thread terminated and replaced), crash/exit -> reject and replace, cancel (`abortOnClose(res)`): queued jobs are dropped, running ones get an abort message and are terminated after a 2 s grace if stuck in synchronous work, `close()` terminates everything. Errors cross as `{kind,name,message}` (`workers/errors.ts`; several of our error classes never set `name`, so `kind` is tagged with `instanceof` in the worker and rebuilt without the constructor on the main thread; no stack is sent). The `RunGate` slot is held until serialize/zip are done. `startServer({workers})` opts in (bin.ts does, from env); `createApp` and `boot()` default to `InlineRunner`, so tests need no build except `server/test/workers.dist.test.ts`, which starts real threads from `dist` (skipped with a warning if `packages/server/dist` is missing; run `npm run build` first) and checks identical output to the inline runner, cancel/timeout/shutdown, and that the event-loop stall of a large preview drops from seconds to milliseconds. A worker cannot load the repo's TypeScript source (`.js` specifiers, no vitest aliases, and `engines >=22.13` predates default type stripping), so never point it at `src`. The MCP server and CLI still generate in-process.

Measured with `npm run loadtest` (accounts mode, one machine, 20,000 rows x 6 columns; `--workers 0` = before): a trivial request during ten concurrent previews waited up to 3.2 s before and 2-5 ms after; event-loop delay P99 1.8 s before, 8 ms after; preview throughput 4 -> 11 req/s, zip export 3 -> 8 req/s (export stops at 4 concurrent because `MOCKDATA_MAX_RUNS` answers 429, by design). Page loads with a session: about 2,300 req/s (SQLite is not a limit). Sign-ins: about 28/s, bounded by password hashing (two at once, a 16-deep queue, then a cheap 503). Remaining limits: one long model-filling run holds a worker for its whole duration (a separate lane for long runs is a later option), each thread has its own heap (`MOCKDATA_WORKER_HEAP_MB`), and `/api/generate` is throttled per user but not gated by `RunGate` (stream and export are). Tests run with a 20 s default timeout (`vitest.config.ts`) because several files start real servers and threads at once.
